# berth M3 (distribution and integration) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make berth installable everywhere the family ships (GitHub Releases for five targets, the npm launcher `@keelstackhq/berth`, `cargo install keel-berth`) through `hoist release`, run it on Windows, and give harnesses (Claude Code first, hull renders it) a jq-free way to drive it: `berth hook <event>`, a `berth` skill and an integration guide.

**Architecture:** Three independent tracks, three PRs. (A) **Windows**: the few Unix-only calls move behind small `cfg` helpers in `sys.rs`/`hooks.rs` (POSIX `sh` lookup, process-tree kill, liveness, hostname), the lock holder record moves to a sidecar file on every OS, `berth env --format pwsh`, and a `windows-latest` CI leg. (B) **Release**: hoist's own layout copied, not reinvented: root `hoist.toml`, `npm/berth` launcher + five platform packages, `pnpm-workspace.yaml`, `.github/workflows/release.yml` (detect, build, publish, prepare), gated by a repository variable so merging it publishes nothing. (C) **Integration**: `berth hook worktree-create|worktree-remove|session-start|statusline` speaks Claude Code's hook protocol on stdin/stdout; `skills/berth/SKILL.md` and `docs/integration.md` are what hull renders; then dogfood and wrap-up.

**Tech Stack:** unchanged (Rust 1.97, edition 2024; clap 4.6.7, serde 1.0.229, serde_json 1.0.154, toml 1.1.8, thiserror 2.0.21; dev: tempfile 3.27.0, assert_cmd 2.2.2, predicates 3.1.4, insta 1.49.0). **No new crate.** Node ≥ 18 for the launcher (tests use `node:test`, no npm dependency). Release workflow: `@keelstackhq/hoist@0.1.0` from npm, pinned exactly.

**Spec:** `docs/superpowers/specs/2026-10-17-berth-design.md` §3 (CLI: `hook`, `--format pwsh`), §7 (formats), §8 (hooks on Windows), §12 (Claude Code), §16 (CI and release), §17 (facts), §18 (milestones). Each task amends what it changes in its own commit.

## Facts verified for this plan (2026-10-22)

Recorded in spec §17 by Task 11.

- **hoist** (`keelstackhq/hoist` @ `8593a37`, spec §9.3, §9.6, §12; its own `release.yml`, `hoist.toml`, `npm/`): a root `hoist.toml` with `[publish] crates = {}` and `github_release = { targets = [...], bin = "berth" }` releases the root crate with tags `v{version}`; `npm/<cmd>/hoist.toml` with `[publish] npm = { launcher = true }` makes `npm/<cmd>` a launcher whose platform packages are `npm/<cmd>-{linux-x64,linux-arm64,darwin-x64,darwin-arm64,win32-x64}` (target map: `x86_64-unknown-linux-musl`, `aarch64-unknown-linux-musl`, `x86_64-apple-darwin`, `aarch64-apple-darwin`, `x86_64-pc-windows-msvc`). The launcher follows the crate's version, has no tag of its own, needs `optionalDependencies` naming exactly the platform packages at the plain version. `release publish --assets dist` expects `dist/<bin>-<target>[.exe]`, creates the tag through the API (no `git push`), the GitHub Release with `SHA256SUMS`, then npm (OIDC, npm ≥ 11.5.1) and crates.io (OIDC trusted publishing). A package missing on a registry is a `pending` human step (`first-publish:<pkg>`), done once with `hoist release bootstrap` from the owner's machine. `publish` refuses outside Actions, off the default branch, or from a job without `environment: release`. **hoist's first release (0.1.0) is itself Blocked** on its owner, so berth's workflow cannot run before `@keelstackhq/hoist@0.1.0` is on npm.
- **The release workflow publishes on the first push to `main`** whose `Cargo.toml` version has no tag (hoist's `detect` rule R19). A GitHub environment that does not exist is created unprotected on first use, so without a gate a merge would tag and create a GitHub Release.
- **Claude Code** (code.claude.com docs, read 2026-10-22: `/docs/en/hooks`, `/docs/en/worktrees`, `/docs/en/statusline`, `/docs/en/permissions`, `/docs/en/skills`): `WorktreeCreate` replaces Claude Code's `git worktree` step for `claude --worktree`, `EnterWorktree`, subagent `isolation: "worktree"` and background sessions; stdin JSON has `session_id`, `transcript_path`, `cwd`, `hook_event_name`, `name` (a slug like `bold-oak-a3f2`); a command hook prints the absolute path as the **last non-empty stdout line**, everything else to stderr; non-zero exit or no path fails creation; paths with `.`/`..` segments or through a symlink below the repo root are refused. `.worktreeinclude` is **not** processed when a `WorktreeCreate` hook exists. `WorktreeRemove` (only for hook-made worktrees) gets `worktree_path`; exit 0 = removed, non-zero fails only if the directory still exists; it never deletes branches. `CLAUDE_ENV_FILE` is given to `SessionStart` (and `Setup`, `CwdChanged`, `FileChanged`) hooks; append `export K=V` lines; later Bash tool calls see them. Statusline stdin has `workspace.current_dir` (= `cwd`), `workspace.project_dir`, `workspace.git_worktree` (linked worktrees). `Read(<path>)` deny rules also block Edit/Write. Project skills live at `.claude/skills/<name>/SKILL.md`; frontmatter `name`, `description`.
- **hull** (`keelstackhq/hull` @ `1994e4b`): no berth plan or template yet; base ships `.claude/settings.json` (PreToolUse `guard.mjs`, SessionStart `session-start.sh` running `.claude/hooks/session-start.d/*.sh`, `Read(.env*)` denied), an opt-in `.claude/statusline.sh`, hull-authored skills. So berth ships the pieces (command, skill text, snippets) and hull's own plan renders them.
- **splice on Windows** (`keelstackhq/splice` @ `6f64cbd`, `src/post.rs`): commands run with POSIX `sh -c` on every OS; on Windows `sh.exe` from `PATH`, else Git for Windows' from `git --exec-path` (`<prefix>/bin/sh.exe` or `<prefix>/usr/bin/sh.exe` for each ancestor of the exec path); missing is exit 3. Windows CI leg with symlink tests gated `#[cfg(unix)]`, `core.autocrlf=false` for test git.
- **Rust on Windows**: `std::fs::File::lock` uses `LockFileEx` over the whole file; it is mandatory, so another handle cannot **read** the locked file (the holder record in the lock file itself would read as "unknown"). `std::fs::rename` replaces an existing target. Today `cargo clippy --target x86_64-pc-windows-gnu` fails on 8 errors: `std::os::unix` in `git.rs` (`OsString::from_vec`), `ports.rs` (`as_bytes`), `hooks.rs` (`process_group`, `ExitStatusExt`), `db.rs` (`mode()`).

## Decisions (made autonomously from the spec; the owner may revisit)

1. **Release gate.** Every job in `release.yml` that writes (`publish`, `prepare`) runs only when the repository variable `BERTH_RELEASE` is `enabled`. Without it a push to `main` runs `detect` only, and `workflow_dispatch` runs `detect` + `build` (+ a smoke run of each binary) as a dry run. The owner flips the variable once hoist 0.1.0 is on npm and the `release` environment exists. This keeps "never publish or tag" true for every merge an agent makes.
2. **First version `0.1.0`** in `Cargo.toml` and all six `package.json`; `publish = false` is dropped and the crate gets `readme`, `keywords`, `categories` and an `include` list (`cargo package --list` shows no tests, fixtures or `npm/`).
3. **hoist from npm**, `npm install -g @keelstackhq/hoist@0.1.0` (exact), in `publish` and `prepare`; no step that holds `GH_TOKEN` compiles anything (hoist's rule). berth's own `detect` copies hoist's awk rule verbatim.
4. **Windows runs hooks with POSIX `sh`** (splice's lookup, exit 3 naming Git for Windows when missing), so `setup`/`teardown`, `createdb` and `docker compose` commands stay one string for every OS. The hook's process tree is killed with `taskkill /T /F /PID <pid>`, liveness is `tasklist /FI "PID eq <pid>" /FO CSV /NH` (a quoted `"<pid>"` field means alive; spawn failure means alive, as today), hostname is `COMPUTERNAME` else `hostname`. All through `std::process::Command`; `#![forbid(unsafe_code)]` stays.
5. **Lock holder in a sidecar** `<lock>.holder` on every OS (written after the lock is taken, emptied before release), because Windows locks are mandatory. One code path, tested on Linux; the lock files themselves keep their names.
6. **Paths from git on Windows** are UTF-8 (`String::from_utf8`, invalid bytes are exit 3 naming the path); `ports::preferred_index` hashes `OsStr::as_encoded_bytes()` (identical bytes on Unix, so the frozen vectors hold).
7. **`--format pwsh`**: `$env:K = 'v'` (single quotes, `'` doubled); hoard token as `$env:TURBO_TOKEN = (Get-Content -Raw -LiteralPath '<token file>').Trim()`, never the value. The `up` next-command hint stays `eval "$(berth env)"` on Unix and becomes `berth env --format pwsh | Out-String | Invoke-Expression` on Windows.
8. **Windows test scope**: the full suite runs on `windows-latest`; tests that need Unix-only features (creating symlinks, exec bits, signals or `SIGKILL` mid-`up`, `#!/bin/sh` fake binaries, the `onlybin` PATH) are `#[cfg(unix)]`, each with a one-line reason. CI stays `ci` (matrix, `fail-fast: false`) + `ci-ok`; required check stays `ci-ok`.
9. **`berth hook <event>`** reads one JSON object on stdin in Claude Code's hook format and writes what the harness expects; it never prints the Report (`--json` is a usage error, exit 2). Events:
   - `worktree-create`: `berth -C <cwd> up <name>`; stdout is only the absolute worktree path (last line), the table and logs go to stderr; exit codes as `up`. An invalid `name` is exit 2.
   - `worktree-remove`: finds the manifest entry whose `path` equals `worktree_path` (from the main checkout of that path's repo) and runs `down <task>` (never `--force`, branch kept: work is never lost; a refusal exits 1 and Claude Code keeps the directory). No entry → exit 0 (already gone).
   - `session-start`: when `cwd` is inside a berth worktree, appends `berth env --format sh` (with `# berth` header) to `$CLAUDE_ENV_FILE`; otherwise, or without `CLAUDE_ENV_FILE`, does nothing; exit 0 unless the file cannot be written (3). No secret value is written (the hoard token stays a `$(cat …)`).
   - `statusline`: reads `workspace.current_dir` (else `cwd`); inside a berth worktree prints `<task> :<PORT>` (one line), else nothing; always exit 0, never takes a lock, reads only the manifest.
10. **Integration content lives in berth** (`skills/berth/SKILL.md`, `docs/integration.md` with the exact `settings.json` hooks, statusline line, `Read` deny rules for `[copy]` paths, `berth.toml` seed and one `CLAUDE.md` line); hull renders it in its own plan. berth does not edit hull.
11. **Decision row for keelstackhq/decisions** is proposed in the final report (not edited here): per-task agent workspaces go through `berth`; `.agents/worktrees.json` (version 1) is the read contract for other tools.

## Global Constraints

All M1 and M2 constraints hold (plans `2026-10-17-berth-m1.md`, `2026-10-21-berth-m2.md`): exit codes, one JSON object on stdout, actions, no secrets in any stream or the manifest, never edit tracked files, atomic writes, lock order repo → user, git via CLI, hermetic tests, snapshots read before accepting, fast checks before every commit, one task per commit with its PROGRESS line and ticked boxes. Additionally:

- No tag is pushed and nothing is published by any task; release jobs that write stay gated (Decision 1).
- Workflow actions pinned to full SHAs with a version comment, as in `ci.yml`. `actionlint` (if installable) on every workflow change.
- Windows checks locally: `cargo clippy --target x86_64-pc-windows-gnu --all-targets --locked -- -D warnings` before every Track A commit; real runs happen on the CI leg.
- New command name `hook` (also in `main.rs` `COMMANDS`); new item kind none (hook prints no Report).

## Review Focus

1. **Merging publishes nothing**: with `BERTH_RELEASE` unset no job can tag, release or publish (Task 7).
2. **No secret leaks** through `--format pwsh`, `hook session-start` (env file) or `hook statusline` (Tasks 3, 9).
3. **`hook worktree-create` stdout is exactly the path** even when setup prints, and `hook worktree-remove` never removes work (Task 9).
4. **Windows parity without `unsafe`**: hook timeouts kill the whole tree; a dead `creating` owner is detected (Tasks 2, 4).
