# berth M1 (core) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `berth` binary whose `up`, `down`, `ls`, `env` and `doctor` give each parallel agent its own git worktree, copied gitignored files, port block, caches, `[env]` values and setup run, recorded in `.agents/worktrees.json`, with locks, rollback and a refusal to lose work.

**Architecture:** Small pure modules (config, env, ports, report) tested as units; thin I/O modules (manifest/registry with atomic writes, locks, git CLI wrapper, copy, hooks) tested against temp git repos; `src/ops/*` wire them into the five commands, each returning one `Report` rendered as a table or one JSON object. No daemon, no network; every command does its work and exits.

**Tech Stack:** Rust 1.97 (`rust-toolchain.toml`, as hoist), edition 2024. Crates (versions checked with `cargo search` on 2026-10-17, pin exactly with `=`): `clap 4.6.7` (derive), `serde 1.0.229` (derive), `serde_json 1.0.154`, `toml 1.1.8`, `thiserror 2.0.21`. Dev: `tempfile 3.27.0`, `assert_cmd 2.2.2`, `predicates 3.1.4`, `insta 1.49.0` (features `json`, `filters`). Decided against (spec §15): `globset` (git matches the patterns itself: `ls-files --exclude=`/`--exclude-from=`), `wait-timeout` (std `Child::try_wait` loop), `dirs`. Locking is `std::fs::File::lock`/`try_lock` (stable since 1.89; verified compiling on 1.97.0 with `TryLockError::WouldBlock`). Ask before adding any other crate.

**Spec:** `docs/superpowers/specs/2026-10-17-berth-design.md` (§3 CLI and exit codes, §4 `berth.toml`, §5 location, §6 manifest/state, §7 env, §8 `up`, §9 ports, §10 copy, §11 other commands, §13 testing, §14 layout, §16 CI).

## Global Constraints

- Names: repo `keelstackhq/berth`, binary `berth`, Cargo package `berth`, lib `berth`, `publish = false` in M1 (crates.io `berth` is taken by an unrelated crate, 0.1.1 on 2026-10-17; M3 renames the package to `keel-berth`, free on that date, before any publish).
- Exit codes: `0` ok · `1` refused or drift · `2` usage (clap usage errors, invalid task slug, `env` without a task outside a worktree) · `3` config or environment error (message says how to fix it). `--help`/`--version` exit 0.
- `--json` prints exactly one object on stdout: `{ "version": 1, "command", "ok", "exit_code", "items": [ { "kind", "key", "action", "reason" } ], "worktrees": [ <manifest entry> ] }`, also for exit-3 errors (one item `kind: "error"`, `action: "refused"`). Logs and hook output go to stderr.
- Actions: `create`, `ok`, `remove`, `drift`, `refused`, `skipped`.
- Task slug `^[a-z0-9][a-z0-9-]{0,47}$`; `task_snake` = task with `-` → `_`.
- Copied file contents and hashes never reach stdout, stderr, `--json`, the manifest or logs; copies are byte-for-byte (`std::fs::copy` to a temp file, rename), never via a `String`.
- berth never edits tracked files; it only appends to `<git-common-dir>/info/exclude`.
- Atomic writes: temp file in the same directory, `sync_all`, `rename`. Lock order repo → user. Lock wait `BERTH_LOCK_TIMEOUT_MS` (default 30000), then exit 3 naming the holder.
- State dir: `$BERTH_STATE_DIR`, else `$XDG_STATE_HOME/berth`, else `$HOME/.local/state/berth` (also macOS).
- Git: CLI only, minimum 2.36 (`worktree list --porcelain -z`); `--path-format=absolute` needs 2.31. No `git2`/`gix`, no HTTP/TLS crate, `#![forbid(unsafe_code)]`.
- Tests are hermetic: `tests/common::berth()` sets `BERTH_STATE_DIR`, `HOME`, `XDG_STATE_HOME` (removed), `GIT_CONFIG_GLOBAL` (empty file), `GIT_CONFIG_NOSYSTEM=1`, author/committer env vars, `TMPDIR` (writable temp dir), and each fixture's `berth.toml` gets a port range from `common::port_range()`; no network, no real `~`.
- Fast checks before every commit: `cargo fmt --check && cargo clippy --all-targets --locked -- -D warnings && cargo test`.

## Review Focus

1. **Re-`up` after `down`** (branch `berth/<task>` kept by `down`): `up` must check out the existing branch instead of failing on `-b`, and get the same ports. Test in Task 10.
2. **Run from inside a worktree or a subdirectory** (`berth up b` from `../repo.berth/a/src`): main checkout, `berth.toml`, manifest and `[worktree].root` resolve from the git common dir, never from the cwd. Tests in Tasks 7 and 10.
3. **Worktree directory deleted by hand** (`rm -rf ../repo.berth/a`): `ls` shows `drift`, `down a` cleans up (prune, ports, manifest) with exit 0, and `up a` works again. Test in Task 11.
4. **Paths and values with spaces and quotes** (repo dir `my repo`, `[env] GREETING = "it's"`): worktree creation, hooks and `env --format sh|fish|dotenv` stay correct; `eval` of the `sh` output round-trips. Tests in Tasks 3 and 10.
5. **Unknown or remote `--base`** (`--base origin/main` never fetched, typo): exit 3 "unknown --base ref `<x>`; berth never fetches, run `git fetch` first", nothing created, no port reserved. Test in Task 10.

### Task 6: Port allocation

**Files:**
- Create: `src/ports.rs`, `tests/ports.rs`

**Interfaces:**
- Produces:
  - `pub fn fnv1a64(bytes: &[u8]) -> u64` (offset `0xcbf29ce484222325`, prime `0x100000001b3`; frozen).
