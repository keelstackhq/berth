# berth M2 (services) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give each task its own database (`[db]` providers `sqlite`, `postgres`, `compose`), a warm turbo cache (seeded from the main checkout, or shared through a running `hoard serve`), and a way to clean up finished work (`berth gc`).

**Architecture:** Two new modules. `src/db.rs`: a pure part (`resolve` turns `[db]` plus task, repo and ports into a `DbPlan`: database name or compose project, URL, the variable to export) and an I/O part (`check_tools`, `check_sqlite`, `create`, `drop`) that runs `createdb`/`dropdb`/`docker compose` through the existing hook runner (own process group, timeout, last-20-lines tail; output to stderr). `src/cache.rs`: `seed_turbo` (hard link or copy of `<main>/.turbo/cache` entries) and `hoard` (reads a running `hoard serve`'s port and token files). `up` gains one step between copy and setup; `down` drops the database after teardown; `gc` is `down` applied to every finished task. Nothing starts or supervises a server (no daemon).

**Tech Stack:** unchanged from M1 (Rust 1.97, edition 2024; clap 4.6.7, serde 1.0.229, serde_json 1.0.154, toml 1.1.8, thiserror 2.0.21; dev: tempfile 3.27.0, assert_cmd 2.2.2, predicates 3.1.4, insta 1.49.0). **No new crate.** External tools are run by the CLI only when the matching feature is configured: `createdb`/`dropdb` (PostgreSQL client), `docker compose` (v2+), `git merge-tree --write-tree` (git 2.38+, optional).

**Spec:** `docs/superpowers/specs/2026-10-17-berth-design.md` §3 (CLI), §4 (`berth.toml`), §6 (manifest), §7 (env), §8 (`up`), §11 (`down`, `doctor`, new `gc`), §12 (hoard), §17 (facts), §18 (milestones). Each task amends the sections it changes in its own commit.

## Facts verified for this plan (2026-10-21)

Recorded in spec §17 by Task 11.

- **turbo cache writes** (source of `crates/turborepo-cache/src/fs.rs` at tag `v2.11.8`, the version example-app pins, and at `main`): the archive (`<hash>.tar.zst`, `CacheWriter::create` then `finish` = temp file + rename), `<hash>-meta.json` (temp + rename) and `<hash>-manifest.json` (`write_atomic`) are always written to a temp file and renamed; eviction unlinks. No entry is rewritten in place, so a hard-linked entry in a worktree never changes the main checkout's copy. Older turbo versions were not checked; `copy` mode exists for them.
- **hoard** (`keelstackhq/hoard` @ `ed8074a`, `src/serve.rs`, `src/config.rs`): `hoard serve` listens on `127.0.0.1`, port random unless `--port`/`HOARD_PORT`, token random unless `--token`/`HOARD_TOKEN`; it writes the port to `./.hoard/port` and the token to `./.hoard/token` (relative to its cwd; `HOARD_PORT_FILE`/`HOARD_TOKEN_FILE` override; `$RUNNER_TEMP/hoard.*` in CI). `hoard env` prints `TURBO_API=http://127.0.0.1:<port>`, `TURBO_TOKEN=<token>`, `TURBO_TEAM=hoard`. `--storage fs` stores under `./.hoard/store`.
- **PostgreSQL 16.15** (local cluster in this container): `createdb --no-password --template=T -- NAME` copies T; when T has another session, createdb waits 5 s, then fails "source database "T" is being accessed by other users" (exit 1). An existing NAME fails "already exists" (exit 1); a missing template fails "template database ... does not exist" (exit 1); no server fails "Connection refused" (exit 1). A 64-byte name is **silently truncated** to 63 (NOTICE only), so berth validates names itself. `dropdb --if-exists` on a missing DB exits 0 (NOTICE); `dropdb` with a live session fails "being accessed by other users"; `dropdb --force` (PG 13+) ends the sessions and drops.
- **Docker Compose v5.6.0** (Docker 29.9.1): `docker compose --project-name P up --detach --wait [svc...]` waits for health checks; `${DB_PORT:-5432}` in the compose file reads berth's exported variables; `docker compose --project-name P down --volumes --remove-orphans` works from any directory **without the compose file** and removes the project's containers and named volumes; a second `down` exits 0 ("No resource found"). Project names must match `^[a-z0-9][a-z0-9_-]*$` (compose says so and exits 1 otherwise).
- **git**: `merge-tree --write-tree` needs git 2.38 (CI runners and this container have 2.43+); berth's minimum stays 2.36, so the squash-merge check is used only when available.

## Decisions (made autonomously from the spec; the owner may revisit)

1. **`[db]` is one table with a `provider`** (`sqlite`, `postgres`, `compose`); keys that do not apply to the provider are a config error (exit 3), like unknown keys. No `[db]` → M1 behaviour, byte for byte (the manifest has no `db` field, snapshots unchanged).
2. **The URL goes to one variable**, `[db].env` (default `DATABASE_URL`; `""` exports none). Default URLs: sqlite `file:<abs path>`; postgres `postgres://[user@]host:port/name` (host `localhost`, port `5432`); compose none unless `[db].url` is set. `[db].url` is a template with the §7 placeholders plus `{db.name}` (postgres name, compose project) or `{db.path}` (sqlite absolute path). `[env]` may use `{db.url}`, `{db.name}`, `{db.path}`. Setting the `[db].env` variable (or `COMPOSE_PROJECT_NAME` with compose) in `[env]` is a config error: one source of truth.
3. **berth never handles a database password.** `createdb`/`dropdb` get `--no-password` (never prompt) and inherit the user's environment, so libpq reads `PGPASSWORD`/`~/.pgpass` itself. berth passes `--host`/`--port` (and `--username` when set) explicitly so the URL and the command always agree.
4. **Names.** postgres default `<repo>_<task_snake>` with the repo name lowercased and every char outside `[a-z0-9_]` turned into `_`; any name must match `^[a-z0-9_]{1,63}$` after expansion (else exit 3 "set [db].name"). compose default project `<repo>-<task>` with the repo lowercased and chars outside `[a-z0-9_-]` turned into `-`, leading `-`/`_` trimmed; must match `^[a-z0-9][a-z0-9_-]*$`. Validated in `up` step 1, before any lock (with a stand-in port block; ports are digits, so the real block cannot change validity).
5. **Ownership and loss.** postgres: berth drops only a database it created, recorded as `db.created = true` in the manifest right after `createdb` succeeds (a crash in between leaks a database rather than dropping someone else's). An existing database of that name makes `createdb` fail (exit 3, nothing dropped). `down` drops the task's database (it is derived dev data made from the template, like the worktree's `node_modules`); a failed drop exits 3 and keeps the entry `removing` unless `--force`, which passes `dropdb --force` and, if that still fails, warns and continues (item `drift`). compose: `down` always runs `compose down --volumes --remove-orphans` for the task's project (per-task name, idempotent). sqlite: the file lives in the worktree and goes with it.
6. **sqlite safety.** The template is a regular file (not a symlink) in the main checkout; a non-empty `<template>-wal` is exit 3 ("checkpoint it or stop the app"), because copying the main file alone would lose committed rows. The target path must be ignored by git (else refused, exit 1, like `[copy]`), or the agent would commit the database. Byte copy via temp + rename; an existing target is `skipped`.
7. **Order in `up`:** copy (§10) → turbo seed → database → setup. The setup hook can run migrations against the new database. Rollback (and `down`): teardown → drop database → remove worktree.
8. **Turbo seeding** is opt-in: `[cache] turbo_seed = "off" | "link" | "copy"` (default `off`, so M1 behaviour stays the default). `link` hard-links each regular file of `<main>/.turbo/cache` (no `*.tmp`, no symlinks, no subdirectories) into `<wt>/.turbo/cache`, falling back to a copy for any file that cannot be linked (other filesystem); `copy` always copies (temp + rename). Seeding is skipped (item `skipped`) when `.turbo/` is not gitignored (it would make the worktree dirty and `down` refuse) or the source is missing. A seed failure never fails `up`: item `skipped` with the error kind, warning on stderr.
9. **hoard export.** `[cache] remote = "none" | "hoard"` (default `none`), `hoard_dir = ".hoard"` (relative to the main checkout, where `hoard serve` writes `port` and `token` when started there). The values are read **live** (the server may restart on another port) and never stored in the manifest or `--json`. `berth env --format sh|fish` prints `TURBO_API`, `TURBO_TEAM=hoard` and `TURBO_TOKEN` as a command substitution that reads the token file (`export TURBO_TOKEN="$(cat '<abs>/token')"`), so the token itself is never printed (CLAUDE.md "never print secrets"); `--format dotenv|json` omit `TURBO_TOKEN` and say so on stderr. Setup and teardown hooks get all three with the real token in their environment (not printed). No server running → nothing exported, a `warning:` on stderr, exit 0.
10. **`berth gc [--dry-run] [--delete-branch]`** removes tasks that are `ready`, whose worktree is a registered linked worktree and clean, whose branch has at least one commit beyond the recorded `base` (a fresh task is never "merged"), and whose branch is merged into the resolved `[worktree].base`. Each removal is `berth down <task>` (same locks, refusals, teardown and database drop; never `--force`). Others are `skipped` with "kept: <why>". `--dry-run` reports `ok` "would remove" and changes nothing. Exit 0; 1 if any `down` refused; 3 if any `down` failed (the other tasks still run; the error becomes an `error` item).
11. **"Merged"** (`git::is_merged`, used by `gc` and `down --delete-branch`) = the branch is an ancestor of base, or (git ≥ 2.38) `git merge-tree --write-tree <base> <branch>` succeeds and yields base's own tree, i.e. every change of the branch is already in base (squash and rebase merges). berth never fetches: it compares with the local base; `git pull` first.

## Global Constraints

All M1 constraints hold (plan `2026-10-17-berth-m1.md`, Global Constraints): exit codes, one JSON object on stdout, actions, no secrets in any stream or the manifest, never edit tracked files, atomic writes, lock order repo → user, git via CLI, hermetic tests, snapshots read before accepting, fast checks before every commit, one task per commit with its PROGRESS line and ticked boxes. Additionally:

- External commands (`createdb`, `dropdb`, `docker`) run only through `hooks::run_hooks` with each argument `sh_quote`d, cwd and env as stated, timeout `[db].timeout_secs` (default 300). `-v` logs them as `berth: hook db: <cmd>` (no passwords exist to leak; the token is never on a command line).
- Tests never need a real database server or Docker: they put fake `createdb`/`dropdb`/`docker` scripts first on `PATH` (`Fixture::fake_bin`). One optional test runs a real PostgreSQL when `BERTH_TEST_PG_BIN` names a directory with `initdb`/`pg_ctl` (local, temp dir, a port from `port_range()`); it returns early with a note when unset (CI), like M1's APFS test.
- New item kinds: `db`, `cache`. New command name `gc` (also in `main.rs` `COMMANDS`).

## Review Focus

1. **Never drop a database berth did not create** (pre-existing name, crash between createdb and the manifest write, config edited after `up`). Tests in Tasks 4, 5.
2. **No secret leaks**: the hoard token and sqlite template contents never reach stdout, stderr, `--json` or the manifest; hooks still get the token. Tests in Tasks 7, 10.
3. **Main checkout's turbo cache untouched** by anything a worktree does after seeding (link mode). Test in Task 6.
4. **gc never removes work**: dirty, unmerged, fresh (no commits) and non-`ready` tasks are kept; squash-merged branches count as merged only with git ≥ 2.38. Tests in Tasks 3, 8.
5. **Rollback** after a failed database step or setup: database dropped (if created), compose project downed, worktree, branch, ports, entry gone; `--keep-on-failure` keeps it `failed` and `down` cleans it. Tests in Task 5.
